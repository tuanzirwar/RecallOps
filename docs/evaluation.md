# 评测说明

运行 `python eval/generate_dataset.py` 会生成一个固定随机种子（`20260901`）的大样本基准：160 条故障（10 条人工风格种子案例 + 150 条合成案例）、960 条有答案查询与 180 条无答案查询，共 1,140 条。查询覆盖错误码精确检索、原始症状、服务名+症状、根因、解决方案和短查询；合成案例包含区域、生产批次和服务依赖，使评测问题保持可区分而不是重复模板。`retrieval_eval.py` 在相同数据、Top-5 和过滤条件下比较 FTS、向量和 RRF 混合检索，生成 HitRate@5、Recall@5、MRR、无答案误召回率、P95 延迟及分查询类型命中率。

- HitRate@5：有答案查询中，Top-5 至少命中一条相关故障的比例。
- Recall@5：对每条有答案查询计算 `Top-5 中相关故障数 / 标注相关故障总数`，再对查询取平均。
- MRR：第一个相关故障排名的倒数在全部有答案查询上的平均值。
- 无答案误召回率：180 条无答案查询中仍返回结果的比例。

相同根因、解决方案或症状可能对应多起独立故障，因此这些泛化查询使用多相关文档标注（qrels）；错误码查询保持单一相关记录。这样不会因为系统返回另一个同样相关的历史案例而被错误计为失败。

当前向量是确定性哈希基线，目的是让仓库在没有外部模型密钥时可复现。扩容数据集是合成基准，不是线上故障数据；报告只能描述该数据集和本地基线。接入真实 Embedding 模型或真实、脱敏并人工标注的故障记录后必须重新运行，不能沿用旧数字。

API 测试覆盖：人工确认、草稿和请求幂等、证据链接、Workspace 隔离、不可信身份拒绝、Revision 与失败后重新索引。提示注入边界由 Skill 与结构化工具返回共同约束；上线前还应增加真实模型的生成评测。
